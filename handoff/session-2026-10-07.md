### The four checks, as they stand

All four are **inter-week**. That is the point: `validate.py` checks a file against itself and
`verify.sh` checks a week against itself, so **nothing in this repo compares a week to its
predecessors** — and rot is by definition change over time. Suggested home: a new
`scripts/drift.py` invoked from `verify.sh`, reading `data/*.json` + `config/sources.yml`.
No network.

**Critical practical point not yet acted on:** checks 3 and 4 have a standing backlog of 29
items between them. Turning either on as blocking without first clearing or grandfathering
the backlog means the next run fails 29 times and the check gets disabled. **Enabling is a
two-step: baseline, then enforce.**

A fifth idea, cheap and not yet specced: emit a machine-readable run log per week,
`runs/<window_start>.json` — per source, URL tried, HTTP status, listing count, which route
won. Today "could not be reached" exists only as prose, so it cannot be diffed or trended,
and nobody can tell whether a venue failed for the first or the seventh consecutive week.

## 6. Traps that cost time today — do not rediscover these

- **`merged: false` from the GitHub API is meaningless in this repo.** `CLAUDE.md` mandates
  local `git merge --no-ff` then push to `main`, so GitHub closes PRs without setting the
  flag. PR #2 reads `merged: false` and **is merged** (`9c94444`). Check ancestry with
  `git merge-base --is-ancestor <sha> main`, never the boolean.
- **WebFetch truncates at 100 KB**, and the truncation looks exactly like a hostile venue.
  That is the whole Roxie story: a 101 KB calendar page stopped the fetch mid-Friday and was
  reported for a week as a venue failure. Check page size before concluding a site is broken.
- **`~/.claude/bin/tool-floor.py` does not exist in this container**, so it exits 2. Known
  since 18 August (see `9c94444`'s commit message). `verify.sh` check 7 plus `ruff check .`
  cover the same floor in-repo. Not a blocker; say so rather than treating it as a skip.
- **Mirror slugs are unconstructible.** A guessed Songkick venue id returned a hotel in
  Northern Ireland, formatted exactly like a correct result. Only ever use a literal URL that
  has been read from somewhere.
- **`note` has `maxLength: 400`** in the schema and `additionalProperties: false` forbids new
  event fields. The gate caught a 409-character note today — trust it.
- **Pushes to `claude/loving-bardeen-v9bqex` 500ed for ~10 minutes** then succeeded. The
  branch had also been deleted on the remote while a stale local tracking ref survived, which
  made `--force-with-lease` refuse correctly. Do not escalate to `--force`; wait and retry.
- **Seasonal zeros make naive rot checks useless.** A zero-after-non-zero check fires ~14
  times on this corpus, almost all legitimate season endings. Suppress with the existing
  `season_ends:` field — which also pressures that field to stay accurate.
- **Deriving thresholds from history ratifies whatever blindness the history contains.** The
  derived floor would *not* have caught SFJAZZ, because SFJAZZ had been read through a
  one-hall mirror for nine weeks and its baseline was already suppressed to the level of the
  fault. This is the single most important design finding; see Addendum 1 of the spec.
- **A known-partial route does not license guessing in which direction the error runs.** The
  digest hedged "assume SFJAZZ has more on than this shows" and that hedge was wrong — the
  Joe Henderson Lab had nothing in the window. An unverified hedge is an unverified claim
  with better manners.
